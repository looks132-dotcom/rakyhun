# 뭉글 0.4.2 · 사내 직접 연결 메신저와 바탕화면 캐릭터

직원 PC끼리 직접 연결합니다. 방장 PC, 클라우드 계정, 유료 서버, 도메인 구매가 필요 없습니다. 각 앱은 대등한 통신 참여자이며, 누군가 퇴근해도 나머지 직원끼리 계속 대화할 수 있습니다.

## 설치와 처음 연결

1. 각 직원 PC에서 `release/Moongle-Setup-0.4.2.exe`를 실행하여 설치합니다. 함께 사용할 모든 직원이 같은 최신 버전으로 업데이트하세요.
2. **사내 연결과 초대 → 기기 로그인 열기**를 누릅니다. 기본 웹브라우저에서 이름·아이디·10자 이상의 비밀번호로 이 PC의 계정을 만듭니다. 로그인 후 설치 앱에 자동 연결됩니다. 계정은 각 PC에서만 사용하며 회사 공용 계정 서버나 Google 로그인은 사용하지 않습니다.
3. 첫 한 명은 **새 모임 만들기**에 팀 이름을 입력합니다. **코드만 복사**로 복사한 43자 초대 코드를 동료에게 전달합니다. 이름·설명·접두사는 복사하지 않습니다. 같은 코드를 여러 직원이 재사용할 수 있습니다.
4. 동료는 같은 사내 네트워크에서 **이 모임 참여**에 동일 코드를 입력합니다. 처음에는 서로 앱을 켜서 동료 목록에 등록하세요. 모임을 만든 직원이 나가도 모임은 유지됩니다.
5. 앱이 같은 모임의 동료를 자동 검색합니다. Windows 방화벽이 묻는 경우 사용하는 사내 **개인 네트워크**에서 앱 통신을 허용해야 합니다.
6. 자동 검색이 사내 Wi-Fi·방화벽·VLAN 정책으로 제한되면, **사내 연결과 초대**에 표시된 동료의 `IP:포트`를 입력하고 **직접 연결**을 누릅니다. IP가 바뀌면 주소를 다시 입력해야 할 수 있습니다.

초대 코드는 그 모임의 연결 비밀키를 포함합니다. 함께 사용할 직원에게만 공유하세요. 모임을 만든 직원도 일반 직원과 똑같이 종료할 수 있으며 관리자 PC를 켜 둘 필요는 없습니다.

**모임 정원은 기본 총 10명**이며 나와 퇴근한 동료도 포함합니다. **연결과 초대 → 모임 인원과 초대 코드 → 최대 인원 → 인원 설정 저장**에서 2~30명으로 조절합니다. 현재 등록된 인원보다 작게 줄일 수는 없습니다. 설정과 등록 동료 목록은 연결된 앱끼리 동기화하며, 미접속 PC는 다시 연결된 후 반영됩니다. 네트워크가 분리된 동안의 등록 현황은 즉시 통합되지 않으므로 중앙 서버의 전역 잠금과 같은 보장은 제공하지 않습니다. 정원이 차면 새로운 기기의 연결에 정원 초과 안내를 표시합니다. 기존 기록과 퇴근한 동료를 자동으로 삭제하지 않습니다.

이전 버전의 `MOONGLE1.` 코드도 입력할 수 있습니다. 예전 안내 문구와 함께 붙여넣거나 코드 앞뒤에 공백·줄바꿈이 있어도 코드를 찾아 읽습니다. 새 43자 코드는 이전 앱이 읽지 못하므로 참여 PC도 0.4.2로 업데이트해야 합니다. Windows 설치 앱의 복사 버튼은 브라우저 클립보드 권한에 의존하지 않고 코드만 직접 복사합니다.

## 바탕화면 캐릭터

- 라운지 안의 그림과 별개로, 동료마다 **독립된 투명 캐릭터 창**이 작업 중인 프로그램 위에 표시됩니다.
- 기본 설정에서는 앱 실행 직후부터 **내 캐릭터**를 표시합니다. 로그인·모임 생성 전에는 퇴근 모습으로 표시합니다. 표시를 꺼 둔 경우 상단 **바탕화면 친구** 버튼으로 다시 켤 수 있습니다. 모니터가 바뀌어 저장 위치가 화면 밖에 있어도 화면 안으로 복구합니다.
- 이름표, 기본 캐릭터 3종·업로드 이미지, 대기 모션·클릭 점프·잡기 흔들림·가끔 걷기·드래그 이동을 지원합니다.
- 미접속 동료도 **퇴근 캐릭터와 이름표가 남습니다.** 퇴근 캐릭터는 움직이지 않고 말풍선도 표시하지 않습니다.
- 내 PC가 퇴근 상태일 때도 대화 말풍선을 숨깁니다. 대화 기록은 메신저 창에 남아 있습니다.
- 캐릭터를 더블클릭하면 별도 메신저를 엽니다. 우클릭 또는 `Ctrl+Shift+Space`를 누르면 **내 캐릭터 머리 위에 작은 입력칸 하나**가 뜹니다. 제목·도구 모음·전송 버튼 없이 Enter로 보내고 Escape로 닫습니다. 다른 곳을 클릭해도 닫힙니다. 입력은 메신저에서 선택한 방으로 전송하며 선택한 방이 없으면 전체 대화로 보냅니다. 로그인과 모임 참여 전에는 연결 설정을 안내합니다.
- **바탕화면에 캐릭터 표시**, **가끔 걸어 다니기**를 설정에서 켜거나 끌 수 있습니다.
- 바탕화면 표시도 모임의 최대 인원 설정에 맞춰 최대 30명까지 지원합니다. 메신저에 현재 등록 인원과 정원을 함께 표시합니다. 캐릭터 위치는 이 PC에 저장됩니다.
- 투명 창의 빈 영역은 클릭을 통과시켜 아래 프로그램을 사용할 수 있게 합니다.

처음 만난 적 없는 미접속 직원은 아직 이 PC가 알 수 없습니다. 한 번 서로 접속해 등록된 동료부터 퇴근 상태로 남습니다.

## 별도 메신저와 대화 기록

상단 **메신저** 또는 트레이의 **메신저 열기**를 누릅니다. 라운지와 분리된 일반 메신저 창에서 대화방, 동료의 접속·퇴근 상태, 이전 대화를 확인하고 메시지를 보낼 수 있습니다. 캐릭터 말풍선과 메신저 창은 같은 메시지를 사용합니다.

메시지는 작성 직후 **내 PC에 먼저 저장**됩니다. 미접속 동료가 있으면 메신저에 **전달 대기**로 표시합니다. 발신자와 수신자의 앱이 함께 접속했을 때 재전송하고 수신 확인 후 대기 표시를 해제합니다. 발신자 앱이 꺼져 있는 동안에는 그 PC의 미전송 메시지를 다른 PC가 대신 전달하지 않습니다.

대화는 참여한 각 PC의 로컬 기록입니다. 새 PC의 전체 과거 기록 자동 복원, 서로 한 번도 함께 접속하지 않은 직원에게 즉시 전달, 인터넷·다른 네트워크에서의 접속은 제공하지 않습니다. 이런 기능에는 별도 보관·중계 장치가 필요합니다.

메신저 왼쪽의 **＋ 대화방 만들기**를 눌러 방 이름을 입력하고 **만들기**를 누르면 바로 새 방으로 이동합니다. 아직 모임이 없으면 메신저의 **모임 만들기 / 참여** 버튼으로 설정 화면을 엽니다. 라운지의 방 이름 옆 **+**도 사용할 수 있습니다. `@이름`으로 멘션하고 **놓친 이야기**에서 안 읽은 대화를 확인합니다. 집중 중에는 멘션·리액션 알림을 보내지 않습니다.

## 접속 종료와 기록 보관

**접속 종료·퇴근하기**는 퇴근 상태로 바꾸며 이전 기록을 계속 확인할 수 있습니다. 다시 **오피스에 접속하기**를 누르면 통신을 재개합니다.

창의 X는 트레이로 숨깁니다. 완전히 종료하려면 **트레이 → 뭉글 종료**를 사용하세요. 정상 종료는 동료들에게 퇴근 상태를 알립니다. 갑작스러운 종료·네트워크 단절은 보통 약 16초의 갱신 만료 후 퇴근으로 표시됩니다. 네트워크 상태나 PC 시계 차이에 따라 달라질 수 있습니다. 화면 잠금·절전 상태도 반영합니다.

- 대화·동료·모임·기기 식별키: `%APPDATA%/moongle-office/lan/lan-history.dat`
- 기기 로그인 계정: `%APPDATA%/moongle-office/device-login/office.json`
- 자동 로그인·캐릭터 위치·표시 설정: `%APPDATA%/moongle-office/settings.json`
- Windows 보안 저장 기능이 가능하면 대화 파일과 자동 로그인 토큰을 암호화합니다. 사용할 수 없는 환경에서는 대화 파일은 일반 로컬 파일로 저장하고 자동 로그인 토큰은 유지하지 않습니다.
- 네트워크 패킷은 모임 비밀키의 AES-256-GCM으로 암호화하고 기기별 Ed25519 키로 서명합니다. 다른 기기의 발신자 ID를 사용할 수 없도록 검사합니다. 표시 이름은 본인이 설정하는 프로필이며 직원 신원 인증을 대신하지 않습니다. 사내 사용을 위한 초기 버전이며 외부 보안 감사를 받은 제품은 아닙니다.
- 모임당 로컬 최근 메시지 10,000개, 방 화면의 최근 300개를 지원하며 기본 정원은 총 10명입니다. 오래된 메시지·미전송 메시지도 보관 한도를 넘으면 제거될 수 있습니다.

앱을 다시 설치하거나 PC를 바꾸기 전에 이 폴더를 보관해야 합니다. 보안 저장으로 암호화한 파일은 다른 Windows 사용자·PC에서 바로 열리지 않을 수 있습니다. 이전 버전의 클라우드·방장 PC 기록은 자동 변환하지 않습니다.

## 사내 네트워크 범위

자동 검색은 UDP 41764의 멀티캐스트·브로드캐스트를 사용하며 실제 대화는 각 앱의 TCP 포트(기본 41765, 사용 중이면 다른 포트)에 직접 연결합니다. 각 앱이 내부적으로 통신 포트를 열지만 별도 서버 프로그램을 설치하거나 운영하지 않습니다. 기기 로그인 웹페이지는 각 PC의 `127.0.0.1` 임의 포트에서만 열립니다.

사내 보안 정책으로 직원 간 통신 자체가 막혀 있으면 자동 검색과 직접 연결 모두 제한됩니다. 이 경우 사내 IT 담당자의 네트워크 허용이 필요합니다. 테스트는 동일 PC의 여러 독립 참여자로 수행했으며 실제 두 물리 PC의 사내 방화벽 환경까지 검증한 것은 아닙니다. 월 과금 리소스는 생성하지 않았습니다.

## 이미지 업로드

PNG/JPG/WebP 3MB 이하를 업로드하면 최대 256px로 줄여 캐릭터에 사용합니다. 공통 호흡·잡기 모션을 적용하며 AI로 새 캐릭터나 애니메이션을 재생성하지는 않습니다. 투명 배경 PNG를 추천합니다.

## 개발과 검증

```text
npm install
npm start
node --test test/*.test.js
node test/desktop-smoke.js
node tools/build.js
node test/desktop-smoke.js --packaged
node tools/preview.js
```

별도 외부 패키지 없이 Node 기본 모듈로 사내 직접 연결을 구현합니다. Electron과 설치 도구는 개발 의존성입니다. `lib/service.js`는 기기 웹 로그인용으로 loopback에서만 실행합니다. 예전 `server.js`는 클라우드 실험용 소스로 남아 있지만 설치 앱에서는 실행하지 않습니다. 유료 배포 설정은 제거했습니다.

검증 항목: 같은 모임 자동 검색, 다른 모임 거부, 메시지 수신 확인·중복 방지, 발신자 위조·변조 패킷 거부, 독립적 종료·퇴근 상태 유지, 메시지·동료·미전송 목록의 재실행 후 유지, 재접속 시 전달. 실제 Electron 창에서 기기 웹 로그인, 캐릭터별 창, 창 위치 이동, 이미지 업로드, 별도 메신저, 퇴근 캐릭터 유지·말풍선 숨김을 검증합니다.

참고 디자인: [Bad Pixel](https://www.badpixel.land/). 원본 캐릭터·이미지·코드는 복제하지 않았습니다.
