# 뭉글 0.3 · 중앙 서버에 연결하는 설치형 채팅앱

직원 PC가 서버 역할을 하지 않습니다. 모든 직원이 같은 클라우드 서비스에 연결하여 각자 접속·퇴근·재접속합니다. 관리자도 다른 직원과 똑같이 앱을 종료할 수 있습니다.

## 현재 상태

- **완료:** 중앙 서버용 코드, 서버를 내장하지 않는 Windows 클라이언트, 웹 로그인 → 앱 연결, 초대 제한, 독립적인 접속·퇴근, 기존 캐릭터·채팅 기능, 배포 설정.
- **개통 보류:** 사용자가 유료 개통을 보류했습니다. Render 서버·디스크를 생성하지 않았고 과금도 시작하지 않았습니다. 소스는 `looks132-dotcom/rakyhun`에 보관했으며 중앙 서버 개통 전까지 클라이언트는 연결 대기 상태입니다.
- `desktop/service-config.json`의 `serverUrl`은 실제 배포 주소가 확인되기 전까지 비어 있습니다. 가짜 서비스 주소를 넣지 않았습니다. 0.3 설치 파일은 클라이언트 검증용이며, 배포 전에는 실제 직원끼리 채팅할 수 없습니다.
- 이전 0.2의 직원 PC 공유 방식은 폐기했습니다. 이번 구조에서는 사용하지 않습니다.

## 화면 확인

`release/Moongle-Preview.html`을 브라우저로 직접 엽니다. 서버 없이 캐릭터·프로필·말풍선·리액션·팀 방·놓친 대화·개별 접속 상태를 체험할 수 있습니다. 미리보기의 동료와 대화는 예시입니다.

`release/Moongle-Setup-0.3.0.exe`는 Windows 설치 마법사입니다. 직원 PC에 Node.js나 별도 서버 프로그램이 필요하지 않습니다. 코드 서명 인증서는 아직 없습니다.

## 실제 개통 후 직원 사용 흐름

1. 같은 Windows 설치 파일을 각자 설치합니다.
2. 앱에서 **웹 로그인**을 누르면 기본 브라우저에서 로그인합니다.
3. 처음 가입할 때는 관리자에게 받은 초대 코드를 입력합니다. 로그인 후 앱이 자동으로 연결됩니다.
4. **연결과 초대 → 접속 종료·퇴근하기**로 퇴근합니다. 로그인 정보는 유지할 수 있습니다.
5. **오피스에 접속하기**로 다시 돌아오거나 앱을 다시 실행합니다. 놓친 대화를 확인할 수 있습니다.
6. 누군가 앱을 종료하거나 PC를 꺼도 다른 직원의 서비스 연결은 유지됩니다. 같은 Wi-Fi에 있을 필요도 없습니다.

배포 주소를 설정한 `desktop/service-config.json`으로 설치 파일을 다시 빌드하면 직원은 서버 주소를 입력하지 않아도 됩니다. 설정 전에 만든 개발용 설치 파일은 **중앙 서비스 연결**에서 실제 HTTPS 주소를 한 번 입력할 수 있습니다.

## 포함된 기능

- 모찌·토리·두부 기본 캐릭터, 업로드 이미지, 캐릭터 이름·프로필
- 호흡·눈깜빡임·클릭·잡기 모션, 드래그 이동, 말풍선
- `Enter` 채팅, 팀별 방, 멘션·놓친 대화·읽음 기록
- 동료 프로필에서 인사·박수·하트 보내기
- 집중 중 멘션·리액션 알림 중지, 전체 알림 켜기·끄기
- 다른 프로그램 위에 표시되는 미니 모드, 전역 `Ctrl+Shift+Space` 채팅
- 화면 잠금은 자리 비움, 절전·연결 만료는 퇴근, 복귀 시 이전 상태 복원

창의 X는 트레이로 숨깁니다. 실제 종료는 **트레이 아이콘 → 뭉글 종료**입니다. 연결이 갑자기 끊기면 약 45초 후 오프라인으로 표시합니다. PC 전원 종료와 네트워크 단절을 구분하는 기능은 아닙니다.

## 배포 구성

`render.yaml`은 **제안된 배포 설정**입니다. 적용하면 유료 웹 서비스와 저장 디스크가 생성됩니다. 아직 적용하지 않았습니다.

- Render Docker Web Service, 싱가포르 리전
- 최소 유료 컴퓨트 `0.5c-512mb`, 단일 인스턴스
- 1GB 영구 디스크 `/var/data`, 앱 데이터 `/var/data/moongle/office.json`
- 로그인 웹페이지와 채팅 API를 같은 HTTPS 서비스에서 제공
- `/health` 상태 검사, `PORT` 환경변수, `SIGTERM` 정상 종료
- 초기 관리자 가입 코드 `MOONGLE_INITIAL_INVITE`는 Render에서 무작위 생성
- Render 기본 서비스 주소 사용, 도메인 구매는 필수 아님

공식 JSON Schema로 `render.yaml` 구조 검증을 통과했습니다. Render 계정에 연결된 CLI/API를 통한 플랫폼 검증·실제 빌드·서비스 개통은 아직 하지 않았습니다. 로컬 환경에 Docker와 Render CLI가 없어 Docker 이미지 실행 검증도 하지 않았습니다.

무료 Render Web Service는 유휴 시 중지되고 영구 디스크를 사용할 수 없어 이 구성의 대체품으로 사용하지 않습니다. 실제 요금과 계정 조건을 확인하고 적용해야 합니다. 영구 디스크 사용 서비스는 단일 인스턴스이며 배포 중 잠시 중단될 수 있습니다. 이 구성은 무중단·무장애를 보장하지 않습니다.

### 배포 순서

1. 소스와 `render.yaml`을 GitHub/GitLab/Bitbucket 저장소에 올립니다. 비공개 저장소를 사용할 수 있습니다.
2. Render에서 해당 Git 저장소 접근 권한을 연결합니다.
3. `render.yaml`의 서비스·디스크·요금을 확인한 뒤 Blueprint를 적용합니다.
4. 실제 서비스의 `/health`와 `/api/config`를 확인합니다.
5. Render 환경변수 화면에서 초기 설정 코드를 확인하여 `/login`의 첫 관리자 가입에 사용합니다. 코드를 소스나 채팅에 붙여 넣지 않습니다.
6. 관리자 가입 뒤 발급된 직원 초대 코드를 전달합니다. 관리자는 이후 앱을 종료해도 됩니다.
7. 실제 HTTPS 주소를 `desktop/service-config.json`에 넣고 Windows 설치 파일을 다시 빌드하여 직원에게 배포합니다.

Render 배포 스킬은 원격 Git 저장소가 없을 경우 저장소 연결 또는 별도 이미지 배포를 먼저 요청하도록 명시합니다. 현재 MCP의 Git 배포 경로에는 원격 저장소가 필요합니다.

## 인증과 데이터

비밀번호는 salt+scrypt 해시로 중앙 서버에 저장합니다. 데스크톱 앱은 브라우저에서 로그인 후 1회용 앱 연결과 별도 검증 키로 토큰을 받습니다. 자동 로그인을 선택하면 Windows 보안 저장 기능으로 각 PC의 토큰을 암호화합니다. 이전 PC 공유 방식의 자격증명은 새 버전에서 재사용하지 않습니다.

프로필·계정·대화·읽음 기록은 중앙 서버에 저장됩니다. 직원 PC에는 서버 데이터베이스가 없습니다. 중앙 서버의 최근 메시지 10,000개, 각 방 화면의 최근 300개를 보관·표시하는 소규모 팀용 초기 버전입니다. 관리자용 계정 복구·추방·보관 정책 설정은 아직 없습니다.

Google 로그인은 OAuth 키를 등록하면 선택적으로 연결할 수 있습니다. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`을 서버 환경변수로 설정하고 서비스 HTTPS 주소의 `/auth/google/callback`을 Google 콘솔에 등록합니다. `PUBLIC_URL`은 사용자 지정 주소를 쓸 때 설정하며 Render 기본 주소는 `RENDER_EXTERNAL_URL`을 사용합니다. 회사 이메일 도메인 제한이 필요할 때만 `GOOGLE_ALLOWED_DOMAIN`을 설정합니다. Google 키는 클라이언트에 포함하지 않습니다. 실제 Google 인증은 자격증명 미제공으로 검증하지 않았습니다. 현재 기본 인증은 웹 아이디·비밀번호입니다.

이미지 업로드는 3MB 이하 PNG/JPG/WebP를 최대 256px로 줄여 공통 모션을 적용합니다. AI로 새로운 캐릭터나 여러 방향 애니메이션을 재생성하는 기능은 아직 연결하지 않았습니다.

## 개발과 검증

```text
npm install
npm run desktop
node --test test/service.test.js
node test/desktop-smoke.js
node tools/validate-blueprint.js
node tools/build.js
node test/desktop-smoke.js --packaged
node tools/preview.js
```

테스트는 중앙 서버를 테스트 프로세스에서 별도로 실행하고 데스크톱 클라이언트가 연결하게 합니다. 테스트용 loopback HTTP는 `MOONGLE_ALLOW_LOCAL_TEST=1`에서만 허용하며 일반 클라이언트 설정은 HTTPS만 허용합니다. 앱을 종료한 뒤 다른 직원 계정이 같은 서버에 여전히 접속하는지 검사합니다.

`node server.js`는 개발 시 localhost:3210에서 웹 로그인과 중앙 API를 실행합니다. 운영 환경은 `NODE_ENV=production`, 데이터 디렉터리, 16자 이상의 초기 설정 코드와 HTTPS 서비스 주소가 필요합니다. `.env.example`은 항목 안내이며 자동으로 로드하지 않습니다. 영구 저장소는 단일 서버에서만 사용해야 합니다.
